Day 30：均衡（EQ）——通道殺成這樣，系統為什麼還能跑？拿雜訊預算贖回頻寬的交易，與三本帳合成一張通道預算表

2026-08-22（六）｜預估學習時間：90 分鐘｜難度：★★★☆☆（觀念課，沒有儀器也沒有新數學——用這一週學過的頻域語言，把工業界最重要的兩個「作弊器」一次講通）
今日目標

第 5 週我們把眼睛弄閉了三次：skin effect（Day 25）、tan δ（Day 26）、ISI（Day 27/29）。今天回答那個懸了一整週的問題——現實裡 10 Gb/s 的訊號天天跑過比我們的 RC 更爛的通道，為什麼沒死？讀完你要能夠：

  1. 用一句話說出均衡（equalization, EQ）的本質：通道的損耗是「確定性的、可預測的」失真，凡是確定性的就可以預先反著做回來——EQ 救得了 ISI，救不了隨機雜訊
  2. 講清楚發射端的 pre-emphasis／de-emphasis：轉態位元加重、連續位元減輕，等於在發射前先把「通道會偏食」這件事反著補償掉；並知道兩者的差別與為什麼工業界常用 de-emphasis
  3. 講清楚接收端的 CTLE（連續時間線性等化器）直覺版：一個「增益蹺蹺板」——低頻壓、高頻抬，用一個 zero 去抵通道的 pole；並知道它的代價：雜訊和串擾不分敵我一起被放大
  4. 建立「拿雜訊預算贖回頻寬」的交易框架：EQ 不是白吃的午餐，它把水平方向的 ISI 問題換成垂直方向的雜訊問題——帳還是要付，只是換一個科目付
  5. 把損耗、串擾、jitter 三本帳整合成一張通道預算表（eye/timing budget）：確定性的線性相加、隨機的 RSS 再乘倍數，並從 Perfect Timing II Ch.3 的實測故事學到「worst-case 直加會把預算算爆」的教訓——替下週 S 參數量測週鋪路

0. 前情提要：這一週，我們親手把眼睛弄閉了

Day 25/26 用頻域語言證明通道是個「偏食的低通」：skin effect 吃 √f、tan δ 吃 f，頻率越高吃越兇。Day 27 說這種偏食在時域的長相叫 ISI——邊沿的起跑點被歷史 pattern 綁架，眼皮長出分身。Day 28 把 jitter 拆成家族樹：隨機的 RJ 用 σ 記帳、確定性的 DJ 用 pk-pk 記帳，合帳用 RSS。Day 29 你（將要）在公司親手用一顆 RC 把這一切疊上示波器。今天是收官：既然通道的病這麼清楚，藥呢？藥有兩帖，一帖在發射端、一帖在接收端，統稱均衡（EQ）。這堂課不需要任何新數學——你這一週學的頻域語言剛好夠用。

白話版：今天在講什麼（公式看不懂的人只讀這格也夠）

把通道想成一副「偏食的耳朵」：低音全收、高音打折。你要隔著這副耳朵講話給人聽，有兩招。第一招（發射端）：說話前先自己把高音的部分喊大聲一點——像對重聽的長輩講話會刻意加重子音（「ㄙ」「ㄊ」這些高頻音），因為你知道那些會被他的耳朵吃掉；等耳朵吃完打折，聽到的剛好是正常音量。這叫 pre-emphasis（預強調）。第二招（接收端）：戴助聽器——助聽器不是把所有聲音變大，是「專門把高音抬起來」的音響 EQ 旋鈕；通道吃掉多少高頻，它就補回多少。這叫 CTLE。但助聽器有個天生缺陷：它分不出高音裡哪些是人話、哪些是背景噪音——一起放大。所以 EQ 是一場交易：你用「垂直方向的雜訊變大」去贖回「水平方向的眼睛張開」。最後一節我們把這一週的三個敵人（損耗、串擾、jitter）寫成一張家庭收支表——每人領多少預算、超支了找誰——這張表就是所有高速介面規格書的骨架。記住三句話就及格：「確定性的失真才救得回來、EQ 不分敵我、預算表確定性直加＋隨機 RSS」。

1. 核心洞見：為什麼損耗「救得回來」，雜訊救不回來

白話版：可逆與不可逆

把一疊鈔票摺成紙飛機——可以攤平復原，因為「怎麼摺的」有規則可循，反著做就好。把同一疊鈔票燒掉——復原不了，因為燒是隨機的破壞，沒有「反著燒」這種操作。通道損耗是摺紙：它對每個頻率打的折扣是固定的、可量的、每次都一樣的（今天量 S21 是這條曲線，明天量還是這條——下週的主角）。雜訊是火：每一次都不一樣，沒有規則可以反著做。EQ 的全部原理就一句話：把通道的折扣表拿來，反著開一張「補償表」。

講正式一點：通道是一個 LTI（線性非時變）系統——它對訊號做的事完全由頻率響應 H(f) 描述（Day 25/26 的語言：|H(f)| 隨頻率下降、相位也在偏）。LTI 的失真是確定性的（deterministic）：同樣的輸入永遠得到同樣的輸出。所以原則上只要串接一個「反通道」E(f)，讓 E(f)·H(f) ≈ 1（在我們關心的頻帶內平坦），失真就被抵消——ISI 消失、分身合併、眼睛張開。

通道：H(f)（低通，|H| 隨 f 下降）
均衡器：E(f) ≈ 1/H(f)（在關心的頻帶內）
合成：E(f)·H(f) ≈ 平坦 → ISI ≈ 0
但雜訊 n 在通道之後才加入：輸出 = E·(H·x + n) = x + E·n　←　雜訊被 E 放大了

白話翻譯：第一到三行是「反著摺回來」——通道吃掉的高頻，均衡器等量補回，合起來像一條透明的線。第四行是今天最重要的一行帳：雜訊是在通道「之後」（接收端附近）混進來的，它沒被通道打折，卻要跟著訊號一起過均衡器的高頻放大——訊號回到原狀，雜訊卻被放大了。這就是「拿雜訊預算贖回頻寬」的數學出處。公式看不懂沒關係，記住：EQ 補的是通道吃掉的，但也順手把通道之後才混進來的髒東西一起養大。

先把界線畫清楚：EQ 救得了誰、救不了誰

救得了：ISI／DDJ（損耗造成的分身——確定性、pattern 相關，Day 27）、通道帶來的邊沿磨鈍（slew 變差→jitter 匯率變差那條帳，Day 29 練習 4，邊沿救回來、匯率就救回來）。救不了：RJ（隨機，無規則可反做）、接收端熱雜訊（在 EQ 之後或跟著被放大）、串擾（它不是「我的訊號被通道打折」，是「別人的訊號闖進來」——CTLE 甚至會把它放大，見第 4 節）。面試最愛考這條界線：把「EQ 能不能解決 jitter」丟給你，正解是拆開答——DDJ/ISI 那部分能、RJ 那部分不能，而且 CTLE 還可能讓高頻雜訊換算出更多 jitter。

2. 第一帖藥：發射端 pre-emphasis／de-emphasis——說話前先把子音喊大聲

白話版：對重聽長輩講話的技巧

回想 Day 27 的賽跑比喻：ISI 的根源是「連續同位元讓電壓爬到很遠的地方，下一個轉態要從很遠的起跑點追回來」。發射端的解法簡單粗暴：轉態的那一個位元，用全力打；連續重複的位元，故意收力。為什麼收力？因為連續位元本來就會讓電壓越爬越遠——你收力，它就爬不遠，下一個轉態的起跑點就不會被拖後腿。從頻域看是同一件事的另一面：轉態多 = 高頻成分，重複多 = 低頻成分；「轉態加重、重複收力」翻譯成頻域就是高頻加料、低頻打折——剛好跟通道的偏食反著來。

2.1 機制：看著自己剛送出的位元決定這一位的力道

實作上發射端根本不用做傅立葉——它只要「記得上一個位元」：這一位跟上一位不同（轉態位，transition bit）→ 全擺幅輸出 Va；這一位跟上一位相同（重複位）→ 縮小擺幅輸出 Vb（Vb < Va）。這其實是一個最簡單的 2-tap FIR 濾波器（本位減掉一小份前一位），但直覺上就是「轉態大力、重複收力」八個字。兩個名詞的差別只在參考點：

  • De-emphasis（去強調）：轉態位維持全擺幅，把重複位往下壓。峰值電壓不變、平均功率下降。工業界常用——例如 PCIe 規範的發射端就是用 de-emphasis 定義的：Gen1 為 −3.5 dB，Gen2 增加 −6 dB 檔位（dB 值 = 20·log₁₀(Vb/Va)，−6 dB 即重複位擺幅約為轉態位的一半）。
  • Pre-emphasis（預強調）：重複位維持原擺幅，把轉態位往上抬。頻譜形狀跟 de-emphasis 等價（差一個整體增益），但峰值電壓變大——受電源軌和 driver 能力限制，所以在「峰值受限」的世界裡大家多半選 de-emphasis。兩個詞在口語中常混用，面試時能講出「差別在參考點與峰值/平均功率」就是加分。
De-emphasis 的帳要誠實記

圖 1 下排那句話值得再講一次：發射端受電源軌限制，峰值就那麼高，所以 de-emphasis 實際上是「把低頻壓下來遷就高頻」——合成響應平坦了，但整體高度（＝接收端拿到的擺幅）變矮。−6 dB 的 de-emphasis 意味著長串重複位元時接收端只拿到約一半的差動擺幅——眼高換眼寬。擺幅變小 = 對雜訊的裕度變小 = 又是那筆「拿雜訊預算贖回頻寬」的交易，只是這次在發射端先付。

3. 第二帖藥：接收端 CTLE——助聽器的蹺蹺板

白話版：音響上的 EQ 旋鈕

CTLE（Continuous-Time Linear Equalizer，連續時間線性等化器）就是接收端的助聽器：一個「低頻壓、高頻抬」的類比濾波器，增益曲線像蹺蹺板——左邊（低頻）沉下去、右邊（高頻）翹起來，翹起的量剛好補通道掉下去的量。它為什麼做得到？回想 Day 29 的 RC 爛通道：一顆 RC 是「一個 pole」——增益從 f3dB 開始以固定斜率下滑。CTLE 的招數是放一個 zero 在同一個頻率——zero 是 pole 的鏡像，讓增益從那個頻率開始以同樣斜率上爬。pole 下滑、zero 上爬，兩相抵消，合成平坦。真實通道不是單一 pole，但「用 zero 抵 pole」的直覺完全成立——CTLE 的可調參數（peaking 量，常見量級為幾 dB 到十幾 dB）就是在調「蹺蹺板翹多高」。

最簡 CTLE：E(f) = (1 + jf/fz) / (1 + jf/fp)，　fz < fp
把 zero 放在通道的 pole 上（fz = f3dB,通道）→ 通道的下滑被抵消
高頻增益 / 低頻增益 = fp/fz（= peaking 倍數）
代價：頻帶 fz～fp 之間的雜訊與串擾同樣被放大約 fp/fz 倍

白話翻譯：第一行是蹺蹺板的數學版——fz（zero）是「開始上翹的頻率」、fp（pole）是「翹到頂、不再翹的頻率」。第二行：把上翹起點對準通道開始下滑的位置，一上一下抵消。第三行：翹了多高？兩個頻率的比值就是倍數（比值 10 = 20 dB peaking）。第四行是帳單：這段頻帶裡的所有東西——訊號、雜訊、隔壁道耦過來的串擾——通通翹同樣的倍數。公式跳過沒關係，記住蹺蹺板和「不分敵我」就好。

3.1 CTLE 不分敵我——這是它跟 TX EQ 最重要的差別

比較兩帖藥的「副作用說明書」，差異在下手的位置：

  • TX de-emphasis 在源頭動手：它調整的是「還沒進通道的乾淨訊號」，此時雜訊、串擾都還沒混進來——所以它不放大任何髒東西。副作用是前面說的擺幅犧牲，以及一個常被忽略的：發射端高頻成分相對變強，對鄰道的攻擊力也變強（Day 24 說過串擾耦合偏愛高頻/快邊沿——你為了自己這條 lane 好而加重高頻，隔壁 lane 收到的串擾就變兇）。單看一條 lane 是解藥，看整把 bus 是外部性。
  • RX CTLE 在末端動手：訊號走完全程才補償，此時雜訊（接收端熱雜訊、電源雜訊）和串擾（沿路耦進來的）已經混在裡面——蹺蹺板一翹，全部一起放大。所以 CTLE 開太兇的典型症狀：眼圖水平方向打開了（ISI 分身合併），垂直方向反而變毛（雜訊增厚）——調 EQ 調到「水平換垂直」的甜蜜點，是接收端 tuning 的日常。
白話版：進階閱讀（一分鐘版 DFE，知道名字就好）

有沒有「只放大訊號、不放大雜訊」的等化器？有——DFE（判決回授等化器）：它不碰進來的類比波形，而是等每個位元「判決完」之後，用已經確定的 0/1 回頭把這個位元會拖給後面的尾巴（Day 27 的殘影）算出來、從後續訊號裡扣掉。因為它扣的是「乾淨的判決結果算出來的量」，雜訊不會被放大——代價是：判決錯一個位元，扣錯的帳會禍延後面好幾位（錯誤傳播），而且它是數位回路，速度與功耗都貴。現代 SerDes 的標準配置就是三帖合用：TX FIR＋RX CTLE＋DFE，各付各擅長的帳。今天記住名字和「不放大雜訊、但會錯誤傳播」這句就夠，正課到週 13 MIPI 再深入。

4. 交易框架：EQ 是拿雜訊預算贖回頻寬

把這一節當成今天的「數學推導」——但推的不是式子，是一筆交易的損益表：

科目沒有 EQ有 EQ 之後誰付的錢
水平：ISI/DDJ（眼寬）分身散開、眼寬被吃掉分身合併、眼寬贖回——（這是買到的東西）
垂直：擺幅（眼高）低頻 pattern 全擺幅TX de-emphasis 把長串位元的擺幅壓低（−6 dB ≈ 一半）發射端付
垂直：雜訊接收端雜訊原樣CTLE 把 fz～fp 頻帶的雜訊放大 fp/fz 倍接收端付
鄰道：串擾原樣TX 高頻加重 → 攻擊力變強；RX CTLE → 收到的串擾被放大整把 bus 一起付
隨機 jitter（RJ）原樣不變（隨機的救不了）；但邊沿變陡 → 雜訊換 jitter 的匯率變好（Day 29 練習 4），這部分間接受益——

看懂這張表，你就懂了為什麼 EQ 不能無限開：每一格「贖回」的旁邊都有一格「付出」。通道爛到某個程度後，把 CTLE 開滿也只是讓雜訊淹掉贖回來的眼寬——這時唯一的解是回頭修通道（換板材、縮短走線、加 retimer），這就是為什麼 SI 工程師的第一志願永遠是「把通道做好」，EQ 是第二志願。

5. 三本帳合成一張表：通道預算表（channel/eye budget）

白話版：家庭收支表

一個 UI（一個位元的時間）就是全家一個月的收入，固定 100%。家裡每個人都要花錢：發射端的 jitter 要一份、通道的 ISI 要一份、串擾要一份、隨機 jitter 要一份、接收端本身「看得清楚一個位元」需要的最小窗口（aperture）要一大份。全部加起來必須小於 100%，剩下的叫 margin（裕度）。超支 = 眼睛閉上 = 系統翻車。所有高速介面的規格書（PCIe、USB、MIPI）本質上都是這張表——規格書規定每個人「最多能花多少」，你設計板子就是在保證你負責的那幾格不超支。記帳規則只有兩條，都是 Day 28 教過的：確定性的（DJ 家族）用 pk-pk 直加；隨機的（RJ）用 σ 記帳、最後乘上目標 BER 對應的倍數（BER 10⁻¹² 約乘 14）。

5.1 一張典型的 eye budget 長這樣

以一條 1 Gb/s 的鏈路為例（UI = 1 ns，數字為教學示意的合理量級，非特定規格）：

項目類型記帳法占 UI
發射端 DJ（DCD、pattern 相關…）確定性pk-pk 直加0.10 UI
通道 ISI/DDJ（損耗，EQ 補償後的殘餘）確定性pk-pk 直加0.25 UI
串擾造成的 jitter（BUJ，保守當確定性記）有界pk-pk 直加0.05 UI
RJ（σ = 10 ps）隨機14 × σ（BER 10⁻¹²，約）0.14 UI
接收端 aperture（setup/hold 的合體＋取樣時鐘誤差）規格直加0.30 UI
合計0.84 UI
Margin0.16 UI

三個讀表重點：①RJ 那行的 14 倍——隨機 jitter 沒有邊界，只能問「要多少倍 σ 才能把出錯機率壓到目標 BER」；10⁻¹² 對應約 14σ（雙邊各約 7σ，Day 28 的高斯尾巴）。②ISI 那行寫的是「EQ 補償後的殘餘」——EQ 的功勞就記在這格變小；沒有 EQ 的話這格可能自己就超過 0.5 UI，全表直接爆掉，這就是「通道殺成這樣系統還能跑」的帳面證據。③margin 不是越大越好，是「夠且可證明」——margin 太大通常代表你為不需要的性能付了成本（更好的板材、更貴的 retimer）。

5.2 Perfect Timing II Ch.3 的教訓：worst-case 直加會把預算算爆

這張表最陰險的坑在「怎麼加」。Perfect Timing II Ch.3 講 timing budget（時鐘版的同一張表：tCLK-to-Q＋tFLIGHT＋tLOGIC＋tSETUP／tHOLD，再加上時鐘自己的 jitter 與 skew），並做了一個誠實到罕見的實驗：拿一棵真實的時鐘樹（25 MHz 振盪器 → 時鐘產生器 → 兩顆 100 MHz ZDB＋兩顆 50 MHz ZDB），先用資料手冊的 worst-case 數字直加算出時序窗口 = 2.0 ns；然後把整棵樹做出來實測——最晚時鐘 +571 ps、最早時鐘 −346 ps，實測窗口只有 917 ps（Perfect Timing II Ch.3）。手冊直加比現實悲觀了一倍以上。為什麼？因為每個手冊數字（jitter、skew、delay）各自內含 guard band，直加等於把所有人的保險疊在一起買——書中稱之為「compounding of guard bands（保護帶的複利疊加）」。

書中給的解方是當年的新參數 TTB（Total Timing Budget）：廠商把 jitter、skew、delay 在全溫度/電壓/頻率/製程範圍內一起特性化成一個保證窗口，避免逐項 guard band 疊加——書中算例：傳統三項直加 1.5 ns → TTB 全頻段 1.3 ns → 固定在 133 MHz 工作時的專屬 TTB 只有 0.696 ns，對 7.5 ns 的週期而言拿回超過 800 ps 的裕度（Perfect Timing II Ch.3）。以現代標準需上修：2002 年的舞台是 100–133 MHz 時鐘與 ns 級窗口，現代高速 SerDes 是 GHz 與 ps 級，且業界後來走向統計法（如 dual-Dirac 模型：DJ 直加、RJ 用 σ 乘 BER 倍數——就是我們 5.1 那張表的記法）而非單一廠商參數；但教訓一字不改：「逐項 worst-case 直加」永遠過度悲觀，「實測」與「統計合成」才是預算表的正道——這也正是下週要學 S 參數量測的理由：預算表裡「通道」那幾格，要靠量測填進真實數字。

6. 實務案例：這些觀念在你的板子上長什麼樣

  • NB 主機板——redriver 與 retimer 的選擇題：筆電裡 USB/DP/PCIe 走線動輒跨過整塊主機板加上一條 FPC，通道預算常常不夠。板廠的兩個標準解你一定見過：redriver（本質就是一顆獨立封裝的 CTLE＋輸出驅動——純類比、便宜、低延遲，但「不分敵我」的原罪全帶著：jitter 不會被重置，它只是把預算表裡「ISI」那格搬小、把「雜訊」那格搬大）；retimer（內含 CDR，把資料重新取樣再發——jitter 預算整張重開，等於把一條長鏈路砍成兩條短鏈路各自記帳，代價是貴、耗電、有延遲、還要跟協定握手）。面試被問「什麼時候用哪個」，用今天的預算表語言答：預算只超支在確定性那幾格（ISI）→ redriver 夠；隨機那格（RJ 累積）也超支 → 只有 retimer 救得了，因為 EQ 救不了隨機。
  • 鏡頭模組——MIPI 為什麼「幾乎」不談 EQ：camera flex 短（量級 5–15 cm），D-PHY 的速率檔位設計上就是讓這種短通道不需要 EQ 也能收——這是 MIPI 與 PCIe 哲學的差異：與其加 EQ，不如把通道規格管住（這就是規格書裡那些 flex 阻抗、插損上限的由來，週 13 正課）。但兩個趨勢正在把 EQ 推進 camera 世界：①解析度/幀率上去後速率往 4 Gb/s 級以上走，較新版 D-PHY 在高速率檔位開始納入接收端等化的規範概念（量級與細節週 13 講，這裡先掛號）；②AR 眼鏡這類產品的 flex 又長又細又要繞鉸鏈——通道爛到傳統「管通道」哲學撐不住，就輪到今天這套交易框架上場。你面 Google AR 職缺時，這條趨勢就是你的談資。
  • FA 現場——「EQ 調到會動」不等於「EQ 調對」：bring-up 時常見的危險操作：眼圖 marginal，把 CTLE/de-emphasis 檔位掃一遍，找到一組會過的就收工。今天的框架告訴你為什麼危險：EQ 檔位是在「水平換垂直」的曲線上滑動，在實驗室常溫下剛好會過的點，可能垂直裕度已經見底——高溫（雜訊上升、通道損耗變大）或換一片板（製程角落）就翻車。正確做法是把掃出來的每一檔都記眼高＋眼寬（或 BER bathtub，下週講），選「兩個方向都有裕度」的檔位，而不是「剛好會過」的檔位。

7. 動手練習（今天動筆不動儀器）

四題全部用這一週的既有知識就能算，算完再展開詳解。

練習 1（用 CTLE 救 Day 29 的爛通道）：Day 29 的 RC 通道 f3dB ≈ 159 kHz（τ = 1 µs）。你要在接收端加一個最簡 CTLE：E(f) = (1+jf/fz)/(1+jf/fp)。(a) fz 應該放在哪？為什麼？(b) 若想把合成頻寬推到約 1.59 MHz，fp 放哪？合成後的系統像什麼？(c) 這顆 CTLE 的高頻雜訊增益是多少倍（幾 dB）？(d) 若接收端在 CTLE 之前的雜訊是 5 mV rms（頻帶內平坦、簡化假設全部落在被放大的頻帶），加 EQ 前後，用 Day 29 的觸發匯率公式 σ_t = v_n/slew 說明 jitter 是變好還是變壞——考慮邊沿變陡與雜訊變大兩個方向。

解：(a) fz = 159 kHz，正對通道的 pole。zero 的上爬斜率（+20 dB/decade）恰好抵消 pole 的下滑斜率（−20 dB/decade）——「用 zero 抵 pole」。(b) fp = 1.59 MHz。抵消後，合成系統 = 一個 pole 在 1.59 MHz 的新低通——等效於「把通道頻寬推高 10 倍」，τ 從 1 µs 變 0.1 µs，原本 1 Mb/s（UI = 1τ，重損耗）的資料現在是 UI = 10τ新，ISI 幾乎消失。(c) 高頻增益/低頻增益 = fp/fz = 10 倍 = 20 dB——159 kHz 到 1.59 MHz 之間的雜訊與串擾照單全放大。(d) 兩個方向拉扯：雜訊 5 mV →最壞情況約 50 mV（×10）；但邊沿 slew 也變陡了——RC 通道 10–90% 邊沿約 2.2τ，從 2.2 µs 變 0.22 µs，slew 快約 10 倍。σ_t = v_n/slew：分子 ×10、分母 ×10，第一階近似打平。但這是「雜訊全部落在被放大頻帶」的最壞假設；實際上雜訊只有一部分頻譜落在 fz～fp 之間，放大不足 10 倍，而 slew 的改善是實打實的——所以通常淨效果是變好，但好的幅度遠小於「眼寬贖回」給人的直覺，這就是甜蜜點存在的原因：fp/fz 再往上開，雜訊放大逐漸吃掉所有紅利。

練習 2（de-emphasis 的帳）：某發射端差動全擺幅 1.0 V（轉態位）。(a) 開 −3.5 dB de-emphasis 後，重複位的擺幅是多少？(b) 開 −6 dB 呢？(c) 通道越爛應該選越深的 de-emphasis——但「越深越好」在哪裡破功？用「長串重複位元期間的接收擺幅」與「接收端雜訊 20 mV rms、判決需要約 ±7σ 裕度」粗算：−6 dB 檔在通道另外再吃掉 14 dB（約 5 倍）的情況下，長串位元的接收擺幅剩多少？夠不夠判決？

解：(a) −3.5 dB → Vb/Va = 10^(−3.5/20) ≈ 0.67 → 重複位約 0.67 V。（b) −6 dB → 10^(−6/20) ≈ 0.50 → 約 0.50 V（「−6 dB ≈ 一半」值得背）。(c) 長串重複位期間接收擺幅 ≈ 0.50 V ÷ 5 ≈ 0.10 V = 100 mV（差動）。判決需要的雜訊裕度：±7σ = ±140 mV——100 mV < 140 mV，不夠，BER 撐不到 10⁻¹²。破功的機制看清楚了：de-emphasis 把低頻（長串位元）的能量犧牲掉換平坦，通道再爛下去，犧牲完剩下的絕對擺幅低於雜訊判決線——水平方向贖回來的眼寬，垂直方向賠光了。這時要嘛降 de-emphasis 深度改靠 RX EQ 分擔、要嘛修通道。順帶一提：這正是規格書把 de-emphasis 做成「檔位」而非固定值的原因——不同長度的通道要配不同深度，太深跟太淺一樣會翻車。

練習 3（預算表實戰）：一條 2 Gb/s 鏈路（UI = 500 ps）。已知：TX DJ = 40 ps pk-pk；通道 ISI 殘餘（EQ 後）= 90 ps pk-pk；串擾 BUJ = 25 ps pk-pk（保守直加）；RJ σ = 8 ps；RX aperture = 150 ps。目標 BER 10⁻¹²（RJ 乘約 14）。(a) 這張表合計多少？margin 剩多少（ps 與 %UI）？(b) 若行銷要求同一條通道跑 4 Gb/s（UI = 250 ps），假設各項 ps 數字不變（實際上 ISI 會更糟——先用不變當樂觀下限），表還過得了嗎？(c) 承 (b)，工程上三個最有力的挽救選項是什麼？各動了表上哪一格？(d) 為什麼「各項 ps 數字不變」是樂觀假設？哪一格在速率翻倍時惡化得最兇、為什麼？

解：(a) DJ 直加：40+90+25 = 155 ps；RJ：14×8 = 112 ps；aperture 150 ps。合計 155+112+150 = 417 ps，margin = 500−417 = 83 ps ≈ 17% UI——健康。(b) 合計仍是 417 ps，但 UI 只有 250 ps → 超支 167 ps，直接爆表，連 aperture 自己（150 ps）都占掉 60% UI。(c) 三個選項對表上格子：①更強的 EQ（TX FIR 加 tap、CTLE 加深、上 DFE）→ 砍「ISI 殘餘」那格（但雜訊帳變差，可能反映在等效 RJ/眼高上）；②換更好的 RX（SerDes 世代升級）→ 砍「aperture」那格（現代 RX 的 aperture 占 UI 比例隨世代下降，量級請查該 IP 規格）；③加 retimer 拆鏈路→ 整張表砍成兩張半程的表各自結算，RJ 累積歸零重記。(d) 最兇的是 ISI 殘餘：UI 減半，同一條通道的「τ 相對 UI」惡化（Day 29 練習 1(d) 的結論），且 Nyquist 頻率翻倍——skin/tanδ 在更高頻吃得更兇（√f 與 f 都是增函數），插損 dB 數上升 → pulse spreading 跨更多 UI。ps 不變的假設違反了這一週學的所有損耗物理，所以 (b) 的「爆表」還是低估的。

練習 4（PT2 Ch.3 判讀）：Perfect Timing II Ch.3 的時鐘樹實驗：手冊 worst-case 直加窗口 2.0 ns、實測 917 ps。(a) 用「guard band 複利」以外的統計語言解釋為什麼直加過度悲觀——哪些成分本質上不會同時到達最壞？(b) TTB 的定義是什麼？它為什麼能比逐項直加小？(c) 書中 TTB 從 1.5 ns（直加）→ 1.3 ns（全頻段 TTB）→ 0.696 ns（固定 133 MHz 的 TTB）——最後這步的省法跟前兩步有什麼本質不同？(d) 把這個教訓翻譯到 5.1 的 eye budget：哪幾行如果用「pk-pk 直加」記其實過度保守？現代預算表怎麼處理？

解：(a) 直加隱含「所有隨機量同時取到自己的極值」——但 jitter 是高斯隨機變數、不同元件的 jitter 互相獨立：兩個獨立高斯同時站上各自 ±極值的機率是各自機率的乘積，天文數字般地小。獨立隨機量的正確合成是 RSS（變異數相加）：√(σ₁²+σ₂²) 遠小於 σ₁+σ₂（Day 28/29 的老朋友，換個場景再登場）。至於 skew/delay 這類「同一顆晶片內相關」的量才適合直加。(b) 書中定義：TTB 是「該元件任何輸出時鐘的所有轉態、相對其輸入參考時鐘，保證落在其中的最大窗口」，涵蓋手冊全部溫度/電壓/頻率/輸入邊沿範圍與製程變異（Perfect Timing II Ch.3）。它比直加小的原因：廠商一次特性化整體行為——jitter、skew、delay 在真實晶片上不會同時最壞，一起量就自動把「不會同時發生」的重疊扣掉，不必每項各留一份保險。(c) 前兩步是「把重疊的保險合併」；最後一步本質不同——它是拿掉一個自由度：F（頻率變異）從變數變成常數（系統固定跑 133 MHz），窗口從 1.3 ns 縮到 0.696 ns，省超過 800 ps。工程含義：規格越貼近你的實際工作點，預算越準——這也是為什麼現代 IBIS-AMI／規格書會給「per data rate」的參數。(d) eye budget 裡 RJ 絕不能 pk-pk 直加（無界，直加沒有意義）——現代做法就是 5.1 表的 dual-Dirac 式記法：DJ 家族 pk-pk 直加（有界、可能同時最壞）、RJ 記 σ 乘 BER 倍數；更進一步的 BUJ（串擾）嚴格說有界但非同時最壞，保守記直加、精算時用統計摺積——下週講 bathtub curve 時會看到這整套記帳法的量測版。

8. 面試怎麼考

EQ 與 budget 是 camera/SerDes 面試的「觀念深度探測器」——背名詞的人講不出交易框架，動過手的人一開口就是損益表。先英文口述，再看參考答案。

Q1: "The eye at the receiver is completely closed, yet the link runs error-free. Explain how transmitter de-emphasis and receiver CTLE make that possible, and what each of them costs you."

參考答案骨架：The channel is an LTI low-pass — skin effect and dielectric loss attenuate high frequencies more than low. That distortion is deterministic: the same input always produces the same output, which means it's invertible in principle. Equalization is exactly that inversion, split across the two ends. At the transmitter, de-emphasis: drive transition bits at full swing and deliberately attenuate repeated bits. In the time domain, that stops the voltage from wandering far during long runs, so every edge starts from the same point — the root cause of ISI removed at the source. In the frequency domain, it's a high-pass shaping that pre-compensates the channel's low-pass. The cost: since the peak voltage is rail-limited, de-emphasis actually lowers the low-frequency content down to match the high — you pay with received swing, roughly half at minus 6 dB, so you trade eye height for eye width. Also, boosting relative high-frequency content makes you a worse crosstalk aggressor to neighboring lanes. At the receiver, CTLE: a zero-pole filter whose rising gain cancels the channel's roll-off — a zero placed on the channel pole. Its cost is fundamental: it sits after the channel, so noise and coupled crosstalk arrive already mixed into the signal and get amplified by the same peaking, roughly the pole-to-zero frequency ratio. That's why I frame EQ as buying back eye width with the noise budget. And the boundary matters: EQ only recovers deterministic impairments — ISI, DDJ. Random jitter has no pattern to invert, so it passes through untouched; if the budget is blown on the random side, no amount of EQ helps — that's when you fix the channel or insert a retimer, which resets the jitter budget by re-sampling through a CDR.

加分點：「deterministic hence invertible」一句話定調；de-emphasis 講出「壓低頻遷就高頻」而非「抬高頻」（顯示真懂峰值受限）；CTLE 的 fp/fz 雜訊帳；主動畫出 EQ 的能力邊界（RJ 救不了）並給 retimer 作為 escape hatch。

Q2: "Walk me through constructing a timing or eye budget for a high-speed link. How do you combine the different contributors, and what's the classic mistake?"

參考答案骨架：Start from one UI as the total budget and list every consumer: transmitter deterministic jitter, residual ISI after equalization, crosstalk-induced bounded jitter, random jitter, and the receiver's sampling aperture. The combination rule depends on the statistics of each term. Deterministic, bounded terms — DCD, ISI, crosstalk — add linearly peak-to-peak, because they're bounded and can plausibly align worst-case. Random jitter is unbounded and Gaussian, so it's characterized by sigma and multiplied by a factor set by the target BER — about fourteen sigma total for ten-to-the-minus-twelve. Sum everything, subtract from the UI, and what remains is margin — which should be positive with headroom across temperature and process, not just on one golden board at room temperature. The classic mistake is worst-casing everything and adding linearly, including the random terms. There's a well-documented example from a Cypress clock-design guide: a real clock tree budgeted from datasheet worst-case numbers gave a 2-nanosecond window, but the fabricated system measured 917 picoseconds — the naive sum was pessimistic by more than two-to-one, because every datasheet number carries its own guard band and independent random contributors never hit their extremes simultaneously. The fix then was a single characterized total-budget parameter; the modern equivalent is the statistical dual-Dirac approach — linear for deterministic, RSS-and-scale for random — plus filling the channel rows with measured S-parameters instead of datasheet pessimism. Over-budgeting isn't conservative engineering, it's paying real money — better laminates, retimers you didn't need — for margin that was never at risk.

加分點：「combination rule depends on the statistics of each term」是整題的題眼；14σ／BER 10⁻¹² 的量化；主動引用 2.0 ns vs 917 ps 的實測故事（有出處的工程故事極少人講得出）；收尾把「過度保守」翻譯成成本語言——資深工程師的視角。

9. 今日 Anki 卡片

Q1：均衡（EQ）的本質一句話？它救得了誰、救不了誰？

A1：通道是 LTI，其失真（損耗/ISI）確定性、可預測 → 可以反著做回來（E(f)·H(f)≈平坦）——EQ 就是通道的反函數。救得了：ISI/DDJ、邊沿磨鈍（連帶改善雜訊→jitter 匯率）。救不了：RJ（隨機無規則可反做）、接收端雜訊（反被 CTLE 放大）、串擾（別人的訊號，不是自己的失真——CTLE 也把它放大）。EQ 開滿仍不過 → 修通道或加 retimer（CDR 重取樣、jitter 預算重開）。

Q2：TX pre-emphasis 與 de-emphasis 的機制與差別？各付什麼代價？

A2：機制＝轉態位全力、重複位收力（最簡 2-tap FIR），時域上讓每個邊沿起跑點拉齊（拔掉 ISI 根源）、頻域上高頻相對加重反補通道偏食。差別在參考點：de-emphasis 壓低重複位（峰值不變、平均功率降）；pre-emphasis 抬高轉態位（峰值變大）——峰值受限世界常用 de-emphasis（PCIe：Gen1 −3.5 dB、Gen2 增 −6 dB 檔；−6 dB ≈ 重複位剩一半）。代價：長串位元接收擺幅縮水（眼高換眼寬）＋高頻加重使鄰道串擾攻擊力變強。

Q3：CTLE 的直覺、數學與致命副作用？

A3：直覺＝增益蹺蹺板（低頻壓、高頻抬）；數學＝E(f)=(1+jf/fz)/(1+jf/fp)，zero 放在通道 pole 上對消，peaking 倍數 = fp/fz（10 倍=20 dB）。副作用：CTLE 在通道之後動手，雜訊與串擾已混入、不分敵我一起放大 fp/fz 倍——症狀：眼寬打開、眼高變毛。對照 TX EQ 在源頭動手不放大髒東西；DFE 用已判決位元扣拖尾、不放大雜訊但有錯誤傳播。調 EQ = 在「水平換垂直」曲線上找兩方向都有裕度的甜蜜點，不是找「剛好會過」。

Q4：eye/timing budget 的記帳規則？RJ 為什麼乘 14？

A4：一個 UI = 100% 預算，消費者：TX DJ、通道 ISI 殘餘（EQ 功勞記在此格變小）、串擾 BUJ、RJ、RX aperture，剩餘 = margin。規則：確定性/有界（DJ 家族）→ pk-pk 直加；隨機（RJ）→ σ × BER 倍數——RJ 無界不能記 pk-pk，BER 10⁻¹² 對應約 14σ（雙邊各約 7σ 的高斯尾巴）。速率翻倍時惡化最兇的是 ISI 格（τ/UI 惡化＋Nyquist 上移、插損更深）。

Q5：PT2 Ch.3 的「直加 vs 實測」故事與教訓？

A5：真實時鐘樹（時鐘產生器＋兩級 ZDB）用手冊 worst-case 直加算出窗口 2.0 ns，實測只有 917 ps（最晚 +571/最早 −346 ps）——直加悲觀一倍以上，因為每個手冊數字自帶 guard band（複利疊加）且獨立隨機量不會同時最壞（正解是 RSS）。書中解方 TTB＝全條件一次特性化的保證窗口：直加 1.5 ns → TTB 1.3 ns → 固定 133 MHz 時 0.696 ns（拿掉頻率自由度，省 800+ ps）（Perfect Timing II Ch.3）。現代上修：ns 級 → ps 級、統計法（dual-Dirac：DJ 直加＋RJ×14σ）＋實測 S 參數填表；教訓不變：逐項 worst-case 直加永遠過度悲觀，過度保守是花真錢買不存在的風險。
