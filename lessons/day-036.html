Day 36：實作實驗指引——TIA/示波器量測 Jitter 與繪製 Bathtub Curve

2026-08-28（五）｜預估操作時間：120 分鐘（含儀器預熱、多次掃描、診斷調整）｜難度：★★★★☆（Perfect Timing II Ch.11 高速探棒原理 + Ch.16 主機板時脈驗證實務，把昨天的 Bathtub 理論「活」起來，親手量出數字、繪出曲線、診斷問題根源）
今日實驗目標

昨天學了 Bathtub curve 是「統計邊沿時刻的誤判率曲線」，但怎麼真正在公司實驗室「量」出來？今天要把示波器變成「jitter 量測工具」，用實際訊號為素材，重現昨天的理論。

  1. 儀器與探棒驗證：確認示波器 / TIA（Timing Interval Analyzer）的頻寬、採樣率、探棒負載與地線問題（Perfect Timing II Ch.11），計算顯示波形的真實失真
  2. 邊沿時刻統計採集：利用示波器的邊沿檢測功能或 TIA，量測 ≥1000 個時鐘週期內所有邊沿到達時刻，繪製時刻偏移直方圖（histogram）
  3. Bathtub 手工繪製：根據邊沿直方圖，計算不同採樣時刻的誤判率（BER），用 log 尺度繪出 U 形曲線
  4. 診斷問題根源：根據 Bathtub 形狀（對稱 vs 不對稱 vs 多峰），反推 RJ/DJ/ISI 的成分，找出改進方向
  5. 實務應用：在 NB 主機板或鏡頭模組的實際訊號上執行上述流程，最少完成 2 條通道的量測

0. 行前檢查：你需要什麼裝備

儀器清單與規格核對

實驗不一定需要最頂級的儀器，但必須符合基本要求。大多數公司的量測室都備有這些；若缺少，可用替代品（見備註）。

1. 第一步：校正儀器與探棒

1.1 示波器自我診斷

目的：確認示波器的實際頻寬、採樣率、記憶體是否足夠量測你的訊號。

  1. 開啟自診斷：示波器的「Utility」或「Help」菜單通常有「Self-Test」選項，執行一遍。檢查頻寬、採樣率是否與規格一致。
  2. 計算採樣點密度：Perfect Timing II Ch.11 提到採樣率與頻寬的比例至少應為 4:1。例如如果你要量 1.6 GHz 的時脈（週期 625 ps），建議採樣率 ≥ 20 Gsps，每個週期至少 ~31 個採樣點。檢查示波器是否達到：
    採樣點數 / 週期 = (採樣率 / 訊號頻率)
    建議值 ≥ 20 點 / 週期（以保證不會遺漏邊沿細節）

    示例：1.6 GHz 訊號 + 20 Gsps 採樣率
    點數 = 20 / 1.6 = 12.5 點 / 週期　　　← 邊界（可用但較緊）

    若點數 < 8，改用 1 GHz 更慢的時脈進行測試，或升級示波器
  3. 檢查記憶體：要量 1000 個週期的完整波形，計算所需記憶體：
    記憶體需求 = 採樣點 / 週期 × 1000 週期 × 樣本位元寬度
    示例：20 點 × 1000 = 20,000 樣本（通常 12-16 bits）
    ≈ 20 KB–40 KB（大多數示波器都有 > 1 MB，足夠）
    確認示波器能以最高採樣率存儲至少 10 μs 的波形資料。

1.2 探棒與地線檢查

目的：消除或定量測量探棒與地線對測量的失真（Perfect Timing II Ch.11 地線電感的計算）。

  1. 測量地線迴路的尺寸：準備一把卡尺或直尺，量測：
    • 地線長度 l（吋，例如 2 吋 = 5 cm）
    • 地線寬度 w（吋，例如 0.5 吋 = 1.27 cm）
    • 地線導線直徑 d（通常 0.02 吋 = 0.5 mm，某些彈簧夾更細）
    利用 Perfect Timing II Ch.11 的電感公式計算：
    L (nH) = 10.16 × [l × ln(2l/d) + w × ln(2w/d)]

    示例：l = 2 吋, w = 0.5 吋, d = 0.02 吋
    L ≈ 10.16 × [2 × ln(200) + 0.5 × ln(50)]
    ≈ 10.16 × [2 × 5.30 + 0.5 × 3.91]
    ≈ 130 nH

    若 L > 150 nH，地線太長；改用彈簧夾或現場焊接（L < 30 nH）
  2. 計算地線的時間常數：結合探棒輸入電容 C（通常 5–10 pF），計算地線對波形的延遲：
    t_GROUND = 3.4 × √(L × C)

    示例：L = 130 nH, C = 5 pF
    t_GROUND = 3.4 × √(130 × 0.005)
    ≈ 3.4 × √0.65 ≈ 3.4 × 0.81 ≈ 2.75 ns

    此延遲會被疊加到示波器的波形上，導致邊沿看起來更鈍

    白話翻譯：如果你的地線造成 2.75 ns 延遲，而你要量測的邊沿本身只有 1 ns 上升時間，示波器最終會顯示 ~3 ns 的邊沿（被地線吃掉了），完全看不到真實的邊沿形狀。

  3. 計算總顯示波形：Perfect Timing II Ch.11 的完整公式：
    t_DISPLAY = √(t_SIGNAL² + t_PROBE² + t_SCOPE² + t_GROUND²)

    示例（Day 35 教學範例的更新版）：
    訊號本身 t_SIGNAL = 100 ps
    探棒 (1 GHz) t_PROBE = 0.338 / 1000 MHz = 338 ps
    示波器 (4 GHz) t_SCOPE = 0.338 / 4000 MHz = 85 ps
    地線 t_GROUND = 2.75 ns（如上例）

    t_DISPLAY = √(0.1² + 0.338² + 0.085² + 2.75²)
    ≈ √(0.01 + 0.114 + 0.007 + 7.56)
    ≈ √7.69 ≈ 2.77 ns

    ← 你看到的邊沿寬度是 2.77 ns，實際訊號只有 100 ps！
    ← 99% 都是地線失真；除非改善地線，否則後續量測都是白搭
  4. 改進方案：
    • 若地線計算出 t_GROUND > 1 ns，必須改用短地線或彈簧夾（目標 < 500 ps）
    • 若現場無法改善（例如 PCB layout 不允許），在「誤差估計」欄記下這個數字，後續所有量測都要 deconvolve 這個延遲
    • 最佳實務：為了量測高速 jitter，最好能讓 t_GROUND + t_PROBE < 300 ps

2. 第二步：採集邊沿時刻直方圖

2.1 目標訊號的選擇

推薦對象：

  • NB 主機板：DDR5 時脈（1.6–2.4 GHz）、CPU 參考時脈（266–400 MHz）、PCIe SRC 時脈（100 MHz 左右）
  • 鏡頭模組：MIPI HS 時脈（1–1.5 GHz）、感光晶片內部時脈（50–500 MHz）
  • 入門選項：若無法接觸上述訊號，可用實驗室函數產生器產生 100–500 MHz 的方波作測試訊號

2.2 示波器設置與採集流程

步驟 1：基本設定

  1. 連接探棒到示波器的 CH1（或其他通道），地線夾到最近的 ground pad
  2. 探棒衰減設定：若訊號幅度 < 500 mV，選 1:1；若 > 1 V，選 10:1（可提高輸入阻抗，減少負載）
  3. 示波器時基（time scale）：設定為訊號週期的 ~2–5 倍，例如 1.6 GHz 時脈（625 ps 週期），設 200–500 ps/div
  4. 垂直放大（vertical scale）：調整到訊號幅度佔螢幕 60–80%，避免飽和與量化誤差
  5. 觸發（trigger）：選「邊沿觸發」（edge trigger），設在上升邊沿或下降邊沿（兩者任選），觸發電位設在信號中間電位（例如 0.5 V）

步驟 2：波形採集

  1. 單次觸發模式：確保示波器設在「正常」或「自動」觸發模式，讓它自動捕捉連續波形（約 1000 個週期以上）
  2. 儲存波形資料：大多數示波器支援「Save/Export」功能：
    • 將波形存為 .csv 或 .txt（包含時刻 t 與電壓 V 的對應）
    • 或直接輸出「邊沿時刻列表」（某些示波器有內建統計功能，見下一小節）
  3. 重複採集 ≥2 次：要驗證波形的穩定性，採集 2–3 次，確認統計結果一致

2.3 提取邊沿時刻（三種方法）

方法 1：示波器內建 Jitter 分析（推薦）

若示波器具有「Jitter」、「Timing」或「Time Interval」分析模式：

  1. 波形匯入後，進入 Jitter/Timing 功能
  2. 設定「邊沿檢測閾值」（通常 50% 幅度，即訊號的中點）
  3. 示波器自動檢測所有邊沿，輸出「邊沿時刻列表」與「時刻偏移直方圖」
  4. 匯出直方圖資料（包括 bin 數、頻數、均值、標準差 σ）

方法 2：手工提取（低階但可靠）

若示波器沒有內建分析，用試算表：

  1. 匯出波形資料（時刻 t 與電壓 V）為 CSV
  2. 在試算表中，用「條件格式」或「查詢函數」找到所有 V 穿過設定閾值的時刻（例如 0.5 V）
  3. 提取這些時刻，記為 t_n（n = 1, 2, ..., N）
  4. 計算邊沿週期 T = 理想週期（如 625 ps），並求 jitter[n] = (t_n − t_{理想})mod(T)
  5. 繪製直方圖：把 jitter 值分成 50–100 個 bin，計算每個 bin 的頻數

方法 3：示波器脈衝寬度或邊沿測量（若無內建統計）

某些示波器能測量單個邊沿的時刻。用「自動測量」（Automeasure）功能：

  1. 設定為「上升時間」或「邊沿到時刻」的自動測量
  2. 示波器逐一量測 1000 個邊沿，產生一個測量值列表（可匯出為 CSV）
  3. 提取這些值，按方法 2 的步驟 4–5 來製作直方圖

白話翻譯：簡單說，你就是要讓示波器「告訴你每個邊沿在什麼時刻到達」。不同示波器機型的操作步驟不同，但概念一樣。如果示波器有自動化功能，就用自動化；沒有的話，用試算表手工提取邊沿，再排隊統計。

3. 第三步：手工計算與繪製 Bathtub Curve

3.1 從直方圖計算 BER（誤判率）

前提條件：你已經有了邊沿時刻偏移的直方圖（jitter 分布）。現在要轉換為「BER vs 採樣時刻」曲線。

基本思路：

假設：
— 邊沿時刻分布記為 PDF(t)（概率密度函數，直方圖正規化）
— 決策電路在時刻 t_sample 採樣
— 邊沿若到達時刻 < t_sample − threshold，被誤判為 0
— 邊沿若到達時刻 > t_sample + threshold，被誤判為 1

則：BER(t_sample) = ∫[−∞, t_sample − threshold] PDF(t) dt + ∫[t_sample + threshold, +∞] PDF(t) dt

簡化（假設 threshold 固定，如 ±25 mV）：
BER(t_sample) = 1 − ∫[t_sample − margin, t_sample + margin] PDF(t) dt

其中 margin 是決策電路對時刻偏差的容許範圍

逐步計算方法：

  1. 正規化直方圖：你的直方圖有 N_bin 個 bin，每個 bin 的頻數為 count[i]。正規化使得總和 = 1：
    prob[i] = count[i] / sum(count)
  2. 掃描採樣時刻：選擇採樣時刻範圍（通常 ±一個 UI 的一半）。例如 1.6 GHz 訊號週期 625 ps，掃描範圍 −300 ps ~ +300 ps（相對於理想邊沿時刻），步長 10 ps：
    t_sample = −300, −290, −280, ..., +290, +300 (ps)
  3. 對每個 t_sample，計算該時刻的「邊沿通過機率」：即直方圖在 t_sample 附近的累積概率。定義一個「決策視窗」（通常 ±一個 sigma，或 ±50 ps）：
    P_correct(t_sample) = ∑[prob[i] for all bin i within (t_sample ± window)]
    BER(t_sample) = 1 − P_correct(t_sample)

    或更嚴格地，用高斯模型（若直方圖形狀接近高斯）：
    BER(t_sample) = Q(margin / σ_RJ)
    其中 margin = |t_sample − t_ideal|（採樣點到理想邊沿的距離）
    σ_RJ = 直方圖的標準差
    Q(x) ≈ 0.5 × erfc(x / √2) ≈ exp(−x²/2) / (x√(2π)) for x > 3
  4. 對數縮放：BER 通常是 10⁻⁹ 以下的極小數字，需要用對數尺度繪製才能看清：
    log_BER(t_sample) = log₁₀(BER(t_sample))

    若 BER = 10⁻¹², log_BER = −12

實例計算：

假設你量到的直方圖如下（簡化）：

時刻 (ps) −20 ~ 0 0 ~ +20 +20 ~ +40 +40 ~ +60 其他
頻數（counts） 50 600 300 45 5
機率 (prob) 0.05 0.60 0.30 0.045 0.005

若決策視窗設為 ±20 ps，掃描採樣時刻：

採樣時刻 t_sample (ps) 視窗內機率 BER = 1 − 視窗內機率 log₁₀(BER)
−40 0.05 0.95 −0.02（~0）
−20 0.05 + 0.60 = 0.65 0.35 −0.46
0 (中心) 0.60 + 0.30 = 0.90 0.10 −1.0
+20 0.30 + 0.045 = 0.345 0.655 −0.18
+40 0.045 0.955 −0.02

3.2 繪製 Bathtub Curve

使用試算表（Excel / Google Sheets）或 Python（matplotlib）：

  1. 準備資料：第一列是採樣時刻 t_sample，第二列是對應的 log₁₀(BER)。例如：
    t_sample (ps) | log_BER
    −100 | −0.3
    −90 | −0.5
    ... | ...
    0 | −2.5 (最低點)
    ... | ...
  2. 繪圖：X 軸為 t_sample（ps），Y 軸為 log₁₀(BER)。選「XY 散點圖」或「折線圖」，應該看到 U 形曲線（浴盆形）。
  3. 標註關鍵點：
    • 浴盆最低點（最小 BER）— 這是「最安全的採樣時刻」
    • ±3σ 位置（若 BER 達 10⁻³）、±4σ 位置（10⁻⁵）、±6σ 位置（10⁻⁹）— 這些是業界常用的「margin 標籤」

白話翻譯：最終得到的圖就是「浴盆」—— 中間深（誤判率高），兩邊淺（誤判率低）。浴盆越淺越好，因為這意味著即使系統有偏差、採樣時刻晚到，也不會掉進高誤判率的陷阱。

4. 第四步：診斷與根因分析

量出 Bathtub 後，根據曲線形狀診斷 jitter 的根源（Day 35 昨天教的「浴盆的三個成分」）。

觀察到的 Bathtub 形狀 推論 下一步檢查
光滑 U 形，對稱 純 RJ（隨機 jitter）主導，系統狀態良好 計算 σ_RJ 與實際規格是否吻合（見下表 「Reference Specification」）
左右不對稱的 U 形 Duty cycle distortion（上下升/下降邊沿不等長） 量測上升邊沿與下降邊沿的分開的 Bathtub（若示波器支援），或檢查終端電阻是否對稱
底部波浪狀，多個低谷 ISI（符號間干擾）或前一位元的 data-dependent jitter 檢查 PCB 走線長度、連接器、通道有無反射（從 Day 33–34 的 S 參數結果對比）；考慮加等化器
浴盆極深（margin 很小） RJ 或 DJ 的方差偏大，系統接近限界 檢查電源雜訊（PDN）、串擾、溫度漂移；可能需要改 layout 或加濾波

實務診斷：NB DDR5 時脈 vs 鏡頭 MIPI HS

場景 1：NB DDR5 時脈診斷

量測結果假設：1.6 GHz DDR5 時脈，Bathtub 呈現略不對稱 U 形，左邊低谷深度 BER = 10⁻⁶，右邊低谷深度 BER = 10⁻⁵，中間寬度 ~100 ps。

根因診斷：

  • 不對稱 → 上升邊沿與下降邊沿的時刻分布不同 → 終端或走線設計有偏差
  • 左邊更深 → 可能上升邊沿驅動強度不足，或走線 return path 異常
  • 寬度 100 ps × 50% duty cycle = 50 ps 的有效決策視窗 → 對 DDR5 來說勉強（通常 target > 100 ps）

對策：檢查 DDR5 時脈的走線（是否有過度的彎曲、via 不對齊），微調終端電阻（假設原來是 50 Ω 並聯 50 Ω，可試試改成 45 Ω + 55 Ω 非對稱），或增加去耦電容以降低電源雜訊。

場景 2：鏡頭 MIPI HS 眼圖診斷

量測結果假設：1.5 GHz MIPI HS 時鐘，Bathtub 底部呈波浪狀，有 3–4 個明顯的低谷，相鄰低谷間距 ~50 ps，最深低谷 BER = 10⁻⁸。

根因診斷：

  • 波浪狀多低谷 → 強烈的 ISI：前一位元的脈衝拖尾還沒消，後一位元就來了 → 邊沿位置被「鎖」在不同的時刻
  • 低谷間距 ~50 ps ≈ UI (667 ps) / 多數據流 → 很可能是「前 1 位元」或「前 2 位元」的影響
  • BER 10⁻⁸ 級別 → 還在可接受範圍，但邊界不舒適

對策：

  • 檢查 flex 走線設計：MIPI 訊號從 sensor → SoC 通常走 flex，多個彎曲會造成反射與 ISI。量測一下 S21（通道衰減），若有諧振峰，改走線布局
  • 加等化器：感光晶片或接收端的 DSP 中通常有可配置的線性等化器，嘗試提升高頻增益（削減 ISI）
  • 改終端：MIPI HS 通常 100 Ω 差動，但若訊號反射較強，可能需要加串聯電阻或調整終端點位置

5. 實驗產出與數據檔案

6. 進階方案與常見卡點

進階方案 A：加外部擾動，驗證 DJ 與 ISI 的分離

場景：Bathtub 底部波浪，你想確認這是 ISI 還是別的 DJ。

做法：用函數產生器產生「預知固定位元序列」（例如 0101010... vs 0011001100...），觀察 Bathtub 形狀是否隨位元序列變化：

  1. 準備兩種位元序列發生器（PRBS / 固定序列，若公司有 BERT 儀器最好）
  2. 將訊號注入測試目標（通常在 PCB 的時脈輸入）
  3. 分別量測每種序列的 Bathtub
  4. 若 Bathtub 形狀隨序列劇變 → 確認是 data-dependent jitter（ISI）；若幾乎不變 → 是環境雜訊（電源 / 串擾）

進階方案 B：轉溫度 / 工作點，驗證 margin 裕度

場景：室溫量測的 Bathtub 剛好通過（margin = 60 ps），但擔心高溫或低電壓時會失效。

做法：

  1. 準備溫控室（或用烤箱 / 液氮，看公司條件）
  2. 在 0°C、25°C、50°C、75°C 各量一次 Bathtub（通常每 25°C 做一次）
  3. 將多條曲線繪在同一圖上，觀察 margin 的溫度漂移
  4. 若高溫時 margin 下降 > 20%，系統風險高，需要設計改進

常見卡點 1：「示波器顯示的波形很模糊，量不出邊沿」

原因 99%：地線失真。

排查步驟：

  1. 檢查地線長度（應 < 1 cm；若 > 3 cm，立即改短）
  2. 計算 t_GROUND（見 1.2 節的公式），若 > 1 ns，改用彈簧夾或現場焊接
  3. 嘗試用更寬的地線（例如寬銅片而非細導線）以降低電感
  4. 若改了還是模糊，考慮是否示波器頻寬不足（升級到 > 4 GHz）

常見卡點 2：「直方圖出現多個尖峰，而不是光滑的高斯」

原因：

  • 可能 A（正常）：訊號確實有 ISI 或 DJ，多峰是真實現象
  • 可能 B（儀器問題）：採樣率太低或示波器時基解析度不足，人為造成「量化誤差」
  • 可能 C（環境問題）：量測環境太吵（例如隔壁在焊接），電源或串擾的干擾進來了

排查步驟：

  1. 提升採樣率（若有 40 Gsps 的示波器，改用 40 Gsps 重新量）
  2. 增加採樣次數（從 1000 週期改成 10000 週期），看直方圖是否更光滑
  3. 試試屏蔽電磁干擾（蓋上導電罩），或改在不同的工作時段（人少、機器少）量測
  4. 若多峰仍然存在且非常明顯 → 確認是 ISI，見進階方案 A（位元序列掃描）

常見卡點 3：「Bathtub 最低點很難找，曲線太平」

原因：系統 jitter 很小（RJ σ < 2 ps），BER 差異不夠大，對數尺度上看不清。

對策：

  1. 加大採樣次數（100000 週期或更多），BER 差異會更明顯
  2. 調整 y 軸范圍（例如只顯示 −2 到 −12，而不是 0 到 −12），放大對比
  3. 用高階統計模型：若直方圖是高斯，用 Q-function 精確計算而非直方圖積分，可得更光滑的曲線

卡 1：Bathtub 量測流程速查表
Q: Bathtub 量測的關鍵 5 步是什麼？（用於快速判斷量測是否完整）

A: ①儀器校正（計算 t_DISPLAY）→ ②邊沿時刻採集 (≥1000 週期的直方圖) → ③直方圖正規化與 BER 計算 → ④掃描採樣時刻，繪 Bathtub 曲線 → ⑤根據形狀診斷 RJ/DJ/ISI

速記：校 → 採 → 算 → 繪 → 診
卡 2：地線電感計算（Perfect Timing II Ch.11）
Q: 為什麼說「地線是量測 jitter 最常見的失誤源」？計算公式？

A: 長地線會造成大電感 L，與探棒電容 C 形成 LC 諧振 → 導致邊沿失真
公式：L (nH) = 10.16 × [l × ln(2l/d) + w × ln(2w/d)]
時間延遲：t_GROUND = 3.4 × √(L × C)，若 > 1 ns，必須改用短地線或彈簧夾

速記：長地線 = 大失真；地線長度 < 1 cm 為佳
卡 3：直方圖到 BER 的轉換
Q: 給定邊沿時刻直方圖，怎麼推算 Bathtub 曲線上某個點的 BER？

A: ①正規化直方圖：prob[i] = count[i] / sum(count) ②選定採樣時刻 t_sample ③計算「視窗內機率」：P_correct = ∑ prob[i] (for bin i within t_sample ± margin) ④BER = 1 − P_correct ⑤取對數：log₁₀(BER)

速記：直方圖的「中心機率越高，邊沿機率越低 → BER 越低」
卡 4：Bathtub 形狀診斷（Day 35 回顧）
Q: Bathtub 曲線的三種常見形狀與其根因？

A:
• 光滑對稱 U 形 → 純 RJ，系統好
• 左右不對稱 U 形 → Duty cycle distortion（上下邊沿不等長）
• 波浪底部（多個低谷） → ISI（符號間干擾，前一位元的脈衝拖尾）

速記：形狀 = 病症；光滑 = 健康；波浪 = 有 ISI
卡 5：Bathtub Margin 解讀（Perfect Timing II Ch.4）
Q: 「採樣時刻 margin」的工程意義是什麼？業界常用的 margin 標籤有哪些？

A: Margin = 採樣點到邊沿統計中心的最大距離（時間空間），確定在該距離下系統還能保持的最大 BER
常用標籤（假設 σ_RJ = 5 ps）：
• 3σ margin (15 ps) → BER ≈ 10⁻³（可接受）
• 4σ margin (20 ps) → BER ≈ 10⁻⁵（很好）
• 6σ margin (30 ps) → BER ≈ 10⁻⁹（業界目標）

速記：更大的 margin = 系統更抗干擾；6σ 是「金標準」
